# Безопасность

Bench — **локальный** инструмент: он поднимает маленький HTTP-сервер на вашей
машине, чтобы отдавать интерфейс браузеру, сохранять планы на диск и проксировать
запросы к LLM-провайдеру (обход CORS). Ниже — как он защищён и на что обращать
внимание.

## Модель угроз и защита

- **Слушаем только `127.0.0.1`.** И статика/`/api` (`serve.py`), и прокси
  (`chat_proxy.py`) по умолчанию доступны только с этой машины. Ни LAN, ни
  интернет достучаться не могут.
- **Открыть в сеть можно только осознанно.** Переменная `TESTER_BIND=0.0.0.0`
  включает доступ по сети — и сервер при старте громко предупредит, что теперь
  любой в этой сети может читать, менять и удалять ваши планы.
- **Прокси пускает к себе только сам конструктор** — по списку разрешённых
  `Origin`. Чужой сайт, открытый в том же браузере, не сможет через прокси ни
  слить ваши переменные окружения, ни ходить от вашего имени.
- **Форвардим только `http`/`https`.** `file://` и прочие схемы заблокированы —
  локальные файлы через прокси не прочитать.
- **Мост «приложение → конструктор» (`/bridge/*`) принимает только
  `application/json`.** «Простой» кросс-доменный POST со стороннего сайта туда
  не пролезет.
- **Ключи API на диск не пишутся.** В плане (`projects/<id>.json`) хранится лишь
  имя переменной окружения (`api_key_env`), а не сам ключ. Значение ключа живёт
  в `localStorage` браузера отдельно от плана и в экспорт не попадает.
- **Обход каталога закрыт.** id проекта строго `[A-Za-z0-9_-]`, зарезервированные
  имена устройств Windows (`CON`, `NUL`, …) отклоняются, запись атомарная.
- **Лимиты.** Потолок тела запроса (8 МБ), потолок ответа провайдера (32 МБ),
  таймауты сокетов — чтобы нельзя было исчерпать память/потоки.

## Что держать в голове

- Не запускайте с `TESTER_BIND=0.0.0.0` в недоверенной сети без необходимости.
- Прокси ходит на тот `base_url`, который вы указали в модели плана — указывайте
  адреса провайдеров, которым доверяете.
- Планы — это обычные JSON-файлы; относитесь к чужим импортируемым планам как к
  недоверенным данным (текст в `notes`/`params` может быть подсказкой для ИИ).

## Сообщить об уязвимости

Нашли проблему безопасности — не открывайте публичный issue. Напишите
сопровождающему через приватный канал (GitHub Security Advisory для репозитория
или e-mail из профиля). Опишите шаги воспроизведения; исправим и укажем вас в
благодарностях.
